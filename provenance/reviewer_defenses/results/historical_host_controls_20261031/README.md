# 港の植物履歴を取得する比較群 — 2026-10-31

目的は H1/H2/H3 の検定で先行記録を持つ蝶だけを事後選択しないこと。既存の14近隣島ペア・41共通新規蝶種記録を固定して、2001–2010年の**一般植物記録の観測機会**で区分した。これは生態的な寄主不在の判定や有意性検定ではない。

| 状態 | 島ペア | 共通新規蝶種×ペア |
|---|---:|---:|
| 一般植物記録が両島100件以上・適合寄主未確認 | **5** | **9** |
| 一般植物記録が両島100件以上・先行適合寄主記録あり | 2 | 3 |
| 一般植物記録が両島100件以上・新規蝶共有0 | 2 | 0 |
| 片側に一般植物記録100件未満 | 5 | 29 |
| **合計** | 14 | 41 |

最優先で植物種別履歴の取得が必要な5島ペア：**81–214（3件）、821–951（2）、276–321（2）、169–715（1）、715–1577（1）**。ここは「寄主が存在しない」9件ではなく「寄主の状態を独立に判断するデータが未取得」9件。取得するのは植物の正規種キー・採集年月・原座標・港/非港・当時の外来区分・調査提供者。既存蝶種×島×年リスク集合の未選択部分へ接続する。

同じ港の5km検索域の記録最大値を島の記録機会の粗い代理とした。重複港の検索域は独立観察ではない。2019年港データは過去の船便でも港が使われた時期でもない。今回の優先群は後から蝶の記録を見て絞った取得対象であり、ここでp値を付けない。

再現：`build_gate.py --out-dir <path>`、3つの入力Git blob固定。元Parquet、制限付き寄主ネットワークや座標は公開・変更しない。
